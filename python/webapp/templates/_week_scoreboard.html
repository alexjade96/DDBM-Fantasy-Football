{# The week's scoreboard as a per-game drilldown. Shared by the Weekly tab, the Overview's current-week section, and the weekly report -- so all three can't drift. Expects `wk_games` (metrics.week_matchups) in context. Each row is one game; expand for both lineups in slot order, benches, and the single legal same-position swap that cost the most. An optional `manager` in context (the weekly report's scoped view) opens that manager's own game by default, so they aren't left hunting a sorted-by-total list for it. `records` (from _week_context, cumulative W-L THROUGH this week) is optional -- `records.get()` degrades to nothing if a caller doesn't pass it. `wk_prefix` and `opt_label` are optional overrides for a caller that includes this template more than once on the same page (e.g. the redraft simulation's one-drilldown-per-week table) -- `wk_prefix` keeps each inclusion's radio ids/names distinct (bare `loop.index0` collided across weeks the first time this was nested inside an outer per-week loop: every week's game 0 shared one radio group and un-toggled each other's panel), and `opt_label` relabels the "Optimized" tab for a caller repurposing opt_lineup/opt_points to mean something other than "same roster, played perfectly" (the redraft table points it at the redrafted roster instead). `opt_default` (bool) points every fact at that relabelled/simulated world instead of the real one, AND switches the SUMMARY row (Winner/Score/Margin, sorted side order) to read `opt_points`/`sim_result`/`g.sim_margin` instead of the real `points`/`result`/`g.margin` -- the summary has to describe the same world as the detail below it. Shipped once without this: a team could be labelled "Winner" (real result, `g.sides` still in real-points order) while the SIMULATED cumulative record sitting right next to its own name (from `records`, which IS sim-based for this caller) showed a loss for that very week -- individually correct numbers that read as contradictory side by side. `g.sides` itself is already re-sorted by whichever world is showing (see draft.redraft_week_matchups), so `a`/`b` below are just "first/second side", not "winner/loser" independent of opt_default. When `opt_default` is set, the REAL roster isn't shown at all: the redraft simulation's Playoffs/Weekly callers are the only ones that pass it, and the real lineup a team actually started has nothing to do with the redrafted roster the simulated score is drawn from, so there is no Actual/Optimized choice to offer -- the drilldown renders the simulated lineup directly, with no toggle. The `dt-facts` line (a REAL-lineup-vs- REAL-optimal efficiency read, with no redrafted-roster equivalent computed) is dropped for the same reason. Callers that leave `opt_default` unset (the plain Weekly/Overview tabs) keep the full Actual/Optimized toggle, unchanged. The summary row is deliberately just 3 symmetric columns -- Winner / Score / Opponent, names flanking inward toward the score -- with the margin folded into the score cell rather than a column of its own, and no separate "Note" column (nail-biter/rout/could-have-won tags): that reads as clutter on a collapsed row when the same "would have flipped it" fact is already one click away in the expanded costliest-call line below. #} {% import "_ident.html" as idm with context %} {% import "_lineupmacro.html" as lu with context %}
