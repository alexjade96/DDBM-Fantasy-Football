## Architecture

### The Pre-season panel data flow
`app._preseason_adp_compare(s, board=None)` (webapp-only, next to
`_preseason_rosters` in `app.py` ~L1727):
- Runs `ffadp.board.combine(str(s.season), scoring=<key>)` -- scoring key
  from `draft._adp_field_for(s)` mapped through `_ADP_FIELD_TO_SCORING`
  (`adp_std->std`, `adp_half_ppr->half_ppr`, `adp_ppr->ppr`, `adp_2qb->2qb`).
- `by_pid` = `{sleeper_id: board_row}` from `b["rows"]`.
- **`sources`** = every `b["sources"]` entry with `group == "apps"`, sorted
  by `_plat_order`, each `{key, label, ok, why}`. Fallback if the board has
  no group info: live columns, then all.
- Per manager (grouped by `user_name`, draft-slot order): per pick builds
  `ranks`/`adps` dicts over `plat_cols`, `consensus`/`spread` from the board
  row, `vs_consensus = pick_no - consensus_rank` (neg = reached ahead of the
  field / green; pos = waited / red). `avg_vs_consensus` = mean over priced
  picks, suppressed if `abs > len(board)` (stub-draft guard, same as
  `_preseason_rosters`).
- Returns `{"sources": [...], "managers": [...]}`. Returns
  `{"sources": [], "managers": []}` when: no draft board, or
  `ffadp.combine` resolved nothing (offline / no snapshot).

## Important Discoveries

- **ESPN has NO 2025 ADP** -- a genuine hole on ESPN's side, not a fetch bug.
  `api.espn_players("2025")` returns 2876 players, every one with
  `ownership.averageDraftPosition == 170.0` (the "undrafted" sentinel;
  `_SENTINEL = 168` filters it). `_trim` -> 0 rows. 2024 has 467 real
  values, so it's not our code. Handoff history already noted "2019 and 2025
  come back all-sentinel from ESPN". Nothing to retrieve or backfill.
- **CBS has NO historical ADP.** `cbssports.com/fantasy/football/draft/
  averages/` ignores every query param (`?season=`, `?year=`, `?yr=`, `?_=`)
  -- always returns the current draft board (Jahmyr Gibbs #1). Archive URLs
  `/averages/2025/` and `/averages/ppr/2025/` 404. Current-season-only is
  correct; `EARLIEST = current NFL season`.
- **RotoWire has NO historical ADP.** `rotowire.com/football/tables/adp.php`
  ignores `&year=`/`&season=`/`&yr=` -- identical byte count, current board.
- **For 2025, `ffadp.combine('2025', scoring='ppr')` resolves**: columns
  `['sleeper','yahoo','ffc']`; `apps` group `['sleeper','yahoo']`; espn
  `ok=False why="unavailable"`, cbs `ok=False why="from 2026"`, rotowire
  `ok=False why="from 2026"`. Committed 2025 snapshots that exist:
  `season/adp/2025.json` (Sleeper), `season/adp/yahoo/2025.json`,
  `season/adp/ffc/{std,ppr,half_ppr,2qb}/2025.json`. **No
  `season/adp/espn/2025.json`, no `season/adp/cbs/`.**
- **`board["sources"]` entries carry `group` and `why` even when
  `ok=False`.** So the full `apps`-group column list (live + dead) is
  derivable from `b["sources"]` directly -- don't use `b["groups"]["apps"]`
  (live only).
- **The webapp dashboard renders CORRECTLY on a freshly-started dev server.**
  Verified end-to-end: `uvicorn webapp.app:app` from `python/`, browser ->
  Draft -> Draft finds -> Pre-season -> expand drilldown -> all platform
  columns present, correct CSS class + padding. A user seeing stale output
  had a dev server started BEFORE the template/CSS edits: **uvicorn
  `--reload` watches `.py` only, NOT `.html`/`.css`**, and `webapp.app`
  holds in-process render/`draft._cache` state. Full stop + relaunch of
  `launch.py dashboard` (not just `--reload`) is required after
