## Architecture

(Only what's needed to continue — see CLAUDE.md for the full picture.)

- **Import resolution is cwd-dependent, not package-installed.** Nothing in
  `fantasy-football-4-fun/` is a real pip-installed package (no
  `pyproject.toml`/`setup.py`). `sleepermetrics`, `webapp`, `webapp.sources.
  {ffadp,nflref}` all resolve because every entry point (`launch.py`,
  `verify.py`, pytest, the Dockerfile's `uvicorn` CMD) runs with cwd set to
  the instance root. Moving any package to a different nesting level
  requires checking every dynamic `__import__(...)` literal too — two were
  found broken this way this session (see Important Discoveries).
- **`tools/parity/paths.py`** is the single source of truth for
  `PY_PACKAGE_DIR` ("fantasy-football-4-fun") and `SEASON_DIR`
  ("data/seasons"), consumed by `export_py.py`/`check_playoffs.py`.
  `export_r.R` has no equivalent module (R has no portable "this file's own
  directory" primitive) and must be kept in sync BY HAND — see its header
  comment.
- **The Dockerfile flattens everything into `/app/`**: `repo_paths.py`,
  `sleepermetrics/`, `webapp/` (which carries `webapp/sources/` nested
  inside it) all become `/app/`-relative siblings, regardless of the real
  repo's nesting. `SLEEPERMETRICS_SEASON_DIR` is set explicitly via `ENV` so
  `repo_paths.py`'s own fallback computation never runs in-container.
- **CI now has 3 jobs** (`.github/workflows/ci.yml`): `python` (pytest),
  `docker-build` (new this session — build-only, `push: false`, catches a
  broken Dockerfile before Render's own auto-deploy would), and
  `deploy-health` (informational — `needs: python` only, waits 120s then
  polls `/health`; Render's auto-deploy itself is independent of CI and
  would redeploy even if CI failed).

## Important Discoveries

- **Two latent bugs surfaced purely by directory moves, neither caught by
  grepping import statements:**
  - `tools/parity/paths.py`'s `REPO_ROOT = Path(__file__).resolve()
    .parent.parent` was correct when the file sat 2 levels deep
    (`parity/paths.py`), silently wrong (pointed at `tools/` instead of
    repo root) once it moved 3 levels deep (`tools/parity/paths.py`).
    Nothing currently imports `REPO_ROOT` so this was latent, not
    live-broken — fixed to `.parent.parent.parent`, verified by import.
  - `ffadp/board.py` and `nflref/base.py` each had a hardcoded dynamic
    `__import__(f"ffadp.{name}", ...)` / `__import__(f"nflref.{name}",
    ...)` fallback (resolving a provider's module-level `EARLIEST`
    constant) that silently returned `None` after the `webapp.sources.*`
    move — caught by 2 real test failures
    (`FIRST_SEASON["yahoo"]` and `test_player_stats_before_earliest_is_empty`),
    not by any import-statement search. Fixed to the new dotted path.
- **`.gitignore` had 3 separate stale-pattern bugs found across this and
  earlier sessions**, all the same root cause (a pattern written for the
  pre-restructure path that doesn't match the new nested one, since
  gitignore patterns containing `/` are anchored): `python/venv/`,
  `season/stats/*/`, `season/nflverse/` (fixed earlier session — had
  already let 20 generated cache files get staged for commit), and
  `parity/out_*.json` (found and fixed THIS session, after the parity/tools
  merge — had already let 2 ~6500-line generated JSON exports get staged).
  **Any future directory move must include an explicit `.gitignore` sweep
  for old path prefixes — this has now bitten 3 separate times.**
- **The network-block fixture immediately proved its own value.** Adding
  `conftest.py`'s autouse `socket.socket.connect` block (to structurally
  enforce "the suite is network-free" instead of relying on every test's
  own monkeypatch discipline) passed 216/216 locally, but on GitHub Actions
  it correctly failed 3 tests that were secretly relying on a same-day
  `sleeperPlayerData_py.pkl` existing on disk (true on this dev machine
  from running the app locally, never true on a clean CI checkout) to
  avoid a live `sleeper_api()` call inside `ffadp.identity`/
  `sleepermetrics.players()`. This is exactly the class of "accidentally
  passes locally, fails in CI" bug the review agent's priority-#1
  recommendation was meant to catch — it caught one on its first real run.
- **`sleepermetrics/__init__.py`'s `from .players import players` shadows
  the submodule of the same name at the package attribute level.**
  `sleepermetrics.players` (attribute) is the FUNCTION, not the module —
  `import sleepermetrics.players as x` still gives you the function via
  attribute lookup, not the submodule, even though
  `sys.modules["sleepermetrics.players"]` holds the real module. Tripped
  up the fix for `test_compare_sources_empty_when_a_source_missing` twice
  before landing on the correct approach: patch the bare name `players`
  where the CALLING module (`nflstats.py`) binds it
  (`from .players import players`), not reach into `sleepermetrics.players`
  at all.
- **8 ffadp provider tests had a real correctness bug, proven by
  simulation, not just suspected.** Each asserted "live endpoint not hit"
  by making the live call raise `AssertionError("live hit")` — but every
  provider's `fetch()` wraps that call in a bare `except Exception`, which
  swallows `AssertionError` too (it IS an Exception), so the test passed
  regardless of call order. Verified by writing a deliberately-regressed
  "live-first" `fetch()` and confirming the OLD assertion still passed
  while the NEW one (a call-counting list) correctly failed.
- **Docker Desktop is not running on this machine and was not started**
  (per standing instruction not to manage dev servers/daemons). All
  Dockerfile-path verification this session was done by manual
  file-existence checks, not an actual `docker build`. The new CI
  `docker-build` job is the first real build-verification this Dockerfile
  has had since the restructures began.
