## Architecture

**The live-week data flow** (only what's needed to continue):

1. `sleepermetrics.fetch_live_week(s, week)` -- fetches ONE week's matchups
   directly from Sleeper (`/league/{id}/matchups/{week}`), shapes them into
   `team_wk`/`pl_wk`/`lineup`-compatible frames. Completely independent of
   `assemble_season`; never touches the real `Season` or its cache.
2. `app._live_week_view(s, scored_leg=None)` -- decides IF a live week
   exists: `/state/nfl`'s live week must be past the REAL `last_scored_leg`
   (fetched via `sm.league()`, since `Season.last_week` floors it to >= 1).
   Returns `(week, live_s, scored_leg)` where `live_s` is
   `dataclasses.replace(s, team_wk=.., pl_wk=.., lineup=..)` -- a throwaway
   view `metrics.week_stats`/`week_matchups` read unmodified.
3. `app._real_scored_leg(s)` -- just the raw `sm.league()` fetch, factored
   out so `_season_phase` and `_live_week_view` can share one call per
   request (passed through as `scored_leg` param).
4. Weekly tab: `_week_context(s, week, allow_zero=.., allow_live=True)`
   adds the STRING sentinel `"live"` to `weeks`; the rail button submits
   `?week=live` but DISPLAYS the real number (`live_week_num`). Numbered
   rail range is capped at `scored_leg` (`numbered_max`), not
   `s.last_week` -- this is why week 1 disappears from the numbered rail
   while still unscored.
5. Overview tab: separate, simpler `_live_week_ctx(s, scored_leg=None)`
   just confirms a live week exists and returns `{"week": wk}` -- the
   template points the shared scoreboard lazy part at `week=live`.

**Insight-tile tie handling** (`app._week_insight_rows`):

- `_extreme(df, col, largest)` returns `(names_list, value)` -- EVERY row
  tied at the max/min, not one arbitrarily chosen by `idxmax()`/`idxmin()`.
- `merged(label, best, worst)` builds each row: single name -> itself;
  2+ tied -> `holder = "N teams"`, `holder_names = "Al, Bo"` (comma only,
  no "and" -- deliberately, to keep the tooltip scannable and distinct from
  the display label). Also drops the "bad" row entirely if it lands on the
  IDENTICAL holder(s)+value as "good" (whole tile tied at one number).
- Templates (`tab_weekly.html` x2, `tab_overview.html`) branch on `r.tied`:
  tied -> plain `<span title="{{ r.holder_names }}">{{ r.holder }}</span>`
  (no portrait); single -> `idm.who(r.holder)` (portrait + avatar lookup,
  which only makes sense for one real manager).

## Important Decisions

- **Decision:** Compare against the REAL `last_scored_leg` (via
  `sm.league()`), never `Season.last_week` or `team_wk`'s own points > 0.
  **Reasoning:** `Season.last_week` floors to >= 1 even before week 1 has
  scored (season.py), so it collides with the live week's own number. A
  live week's `team_wk` rows carry the SAME partial data this function
  would re-fetch, so "does team_wk have positive points" (`_last_completed_
  week`) also falsely reads a live week as "complete" the moment any game
  posts a score. Both were real, shipped bugs this session found and fixed
  across THREE call sites (`_live_week_view`, `_season_phase`,
  `_week_context`'s `wants_numbered`) -- each one initially missed the
  bug the other two had already been fixed for. If touching this area
  again, grep for `last_week` and `_last_completed_week` and check every
  caller assumes the FLOORED/inferred value is safe before reusing it.

- **Decision:** A bare/blank Weekly-tab request defaults to "live" ONLY
  when `numbered_max >= 1` (a genuine completed week exists), never
  `numbered_max >= lo`. **Reasoning:** `lo` is 0 whenever `allow_zero=True`
  (the Pre-season/draft slot is offered) -- comparing against `lo` treated
  "week 0 (draft) exists" as if it meant "a completed numbered week
  exists," which is wrong; week 0 is never a substitute. This was a real
  regression introduced mid-session and caught by the user reporting
  "insights reverted to a prior version."

- **Decision:** Ties render as "N teams" + a `title=` hover tooltip
  (comma-separated names, no "and"), NOT a joined display string like "Al
  and Bo" inline. **Reasoning:** joined names in the visible label
  overflowed the tile's fixed width once ties made holder names longer
  than one manager name; user explicitly asked for the "N teams" +
  hover-reveal design over listing names inline.

- **Decision:** Live-week insight-tile wording is hand-tuned per tile, not
  one qualifier ("current"/"so far"/"currently") stamped everywhere.
  **Reasoning:** Went through several rounds of user feedback rejecting
  mechanical find-and-replace phrasing ("current lineup efficiency" didn't
  differentiate good/bad; "of the optimal lineup so far" doesn't
  grammatically parse; "toughest opponent so far" needed a verb). Final
  per-tile wording (see Constraints below) is the result of this
  iteration -- don't re-flatten it to one shared qualifier without asking.

- **Decision:** Two commits, not one. **Reasoning:** user wanted this
  session's live-week work separated from the unrelated pre-existing ADP
  changes that happened to be sitting in the working tree; keeps history
  traceable to what each commit actually changed.

## Important Discoveries

- `Season.last_week` (season.py) is `max(last_scored_leg, 1)` -- looks like
  "the last real week" but is actually a UI-safety floor. Any code that
  needs "has ANYTHING actually finished scoring" must NOT read this field;
  it must fetch the raw `league()` object's `last_scored_leg` directly.
- A live/in-progress week's `team_wk` rows (inside the REAL, cached
  `Season`, not just the throwaway live view) already contain the same
  partial/live points Sleeper is currently serving -- `assemble_season`
  fetches week 1..last_scored_leg's matchups regardless of whether
  Sleeper considers them "final," and Sleeper answers live partial scores
  for an in-progress week's matchups endpoint too. This means "does
  team_wk have points > 0" is NOT a safe proxy for "is this week done" --
  it conflates live-partial with finished.
- `idm.who()` (`_ident.html`) is strictly single-name (does an
  `avatars.get(name)` lookup) -- no multi-name precedent existed anywhere
  in the codebase before this session. Tied rows deliberately bypass it.
- `.ident .idn`'s `overflow: hidden; text-overflow: ellipsis; white-space:
  nowrap` never actually engaged before this session's CSS fix -- a flex
  ITEM needs its own `min-width: 0` to shrink below content width, which
  `.idn` never had. This was a latent, pre-existing gap (not tied-name
  specific) that just never got exercised because names were always short
  before ties could join multiple names together.
- The project's own writing-style convention (`--` not em dashes) was
  already fully followed everywhere in `python/sleepermetrics`,
  `python/webapp` (templates, app.py) EXCEPT one pre-existing file,
  `python/webapp/static/builder.js` (8 occurrences) -- fixed on request.
  `_adp_compare.html` (unrelated ADP work) still has one `&mdash;` left
  in -- user explicitly said leave it (not this session's file to fix).

- Insight-tile detail-text final wording (do not regress without asking):
  - Scoring: `"current highest score"` / `"current lowest score"` (live);
    `"high score of the week"` / `"low score of the week"` (completed).
  - Efficiency: `"best lineup efficiency so far"` / `"worst lineup
    efficiency so far"` (live, DIFFERENT text per row); `"of the optimal
    lineup started"` (completed, SAME text both rows -- the % differentiates).
  - Bench: `"fewest bench points so far"` / `"most bench points so far"`
    (live); `"fewest bench points"` / `"most bench points"` (completed).
  - Luck: `"current lowest winning score"` / `"current highest losing
    score"` (live); `"won with the week's lowest winning score"` / `"lost
    with the week's highest losing score"` (completed).
  - Opponent: `"currently facing the weakest opponent"` / `"currently
    facing the toughest opponent"` (live); `"weakest opponent this week"` /
    `"toughest opponent this week"` (completed).
  - Margin: `"current largest lead"` / `"current closest game"` (live);
    `"biggest win of the week"` / `"closest game of the week"` (completed).
- Completed-week wording must stay byte-identical to what it was before
  this session (verified via existing tests) -- only the `live=True` path
  changed.
- Overview tab: live section shows ONLY the scoreboard (no tiles/charts);
  "What happened last week" section shows ONLY tiles/charts (no
  scoreboard drilldown -- that detail lives on the Weekly tab, linked).
- Weekly tab: live section shows the six-tile insights + live scoreboard,
  but NOT Best of the Week, NOT the context charts (week_race/
  week_matchups), NOT the recap narrative.
- Don't touch `python/ffadp/*`, `table-sort.js`, `_adp_compare.html`,

## Rejected Approaches

- **Rejected:** Joining tied names into one visible string ("Al and Bo",
  "Al, Bo, and Cy") directly in the tile label.
  **Why:** overflowed the tile's fixed-width column once names got long;
  user asked for "N teams" + hover-tooltip reveal instead.
- **Rejected:** One shared "current"/"currently" qualifier stamped
  identically across all six live-tile wordings.
  **Why:** produced ungrammatical or non-differentiating text in several
  tiles (Efficiency's two rows read identically; "of the optimal lineup so
  far" doesn't parse; "toughest opponent so far" needed a verb). Each tile
  now has its own hand-checked wording (see Constraints).
- **Rejected:** Comparing the live week against `s.last_week` (the floored
  value) to decide if a live week exists.
  **Why:** collided with week 1 while in progress -- see Important
  Decisions above. This was tried, shipped, found broken, and fixed to use
  `_real_scored_leg` instead; do not revert to `s.last_week` for this
  check.
- **Rejected:** Inferring "week is complete" from `team_wk`'s own
  `points > 0` (`_last_completed_week`) for the Overview's `_season_phase`
  gate. **Why:** a live week's `team_wk` already carries partial/live
  points from the same feed, so this signal can't distinguish "genuinely
  done" from "in progress with an early score already posted." Switched
  `_season_phase` to `_real_scored_leg` instead; `_last_completed_week`
  itself is UNCHANGED and still correctly used elsewhere (`_has_scored_data`),
  just no longer used for THIS specific decision.
- **Rejected:** `numbered_max >= lo` as the "does a completed week exist"
  check in `_week_context`'s bare-request handling.
  **Why:** `lo` is 0 whenever the draft/Pre-season slot is offered, which
  made "week 0 exists" look like "a completed week exists" -- a real
  regression the user caught ("insights reverted to a prior version").
  Fixed to `numbered_max >= 1`.
- **Rejected:** Rendering one avatar portrait per tied name (looping
  `idm.who()` per name in a tied row). **Why:** user chose the simpler
  plain-text "N teams" + tooltip approach; no template restructuring
  needed, `idm.who()` stays single-name-only everywhere.
- **Rejected:** Dropping the tied-out row entirely instead of listing/
  naming ties (Option B from an earlier round). **Why:** user picked
  "list all tied names in one row" (Option A) since ties are common
  enough (esp. Bench = 0.0 for several teams) that dropping rows would
  make tiles vanish too often.
