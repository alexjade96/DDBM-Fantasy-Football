## Architecture

### ffadp data flow
`combine(season, scoring, pos, reload)` -> for each provider in `PROVIDERS`:
`fetch(season, scoring, reload=)` (snapshot-first; degrades to `[]` on any
failure) -> `identity.resolve()` fills `sleeper_id` for rows without one ->
merge by `_key_of` (`sid:<id>` or `nm:<norm>|<POS>`) -> per row compute
`consensus` = round(mean of available ranks, 1), `spread` = max-min (None if
<2) -> sort by consensus asc. `columns` is then reordered by group; `groups`
list built. A source returning `[]` is dropped from `columns`, tagged in
`sources` with `why` (`"from <year>"` / `"no public data"` / `"unavailable"`).

### Snapshot-first / reload
Default: committed/mem snapshot used; network only for a missing year.
`reload=True` (from `?reload=1`) bypasses snapshots, re-fetches, rewrites.
`combine('2024', scoring='ppr')` with no snapshots missing = 0 live calls
(verified).

### The Sources filter (client-side, `_adp_compare.html` script IIFE #2)
The checkboxes live in `#adp-controls` (outside `#adp-board`) so they survive
table swaps. On `change` (and on load, and after every `#adp-board`
`htmx:afterSwap`), `apply()` does three things:
1. `applyColumns(t, on)` -- toggles `.adp-col-hidden` on every
   `[data-adp-group]` element whose group is unchecked; recomputes the
   `.adp-groupedge` left divider on the first visible col of each later group.
2. `recompute(t, on)` -- for each body row, collects `data-rank` from the
   `td[data-adp-col]` cells whose column's group is checked, then rewrites
   the row's `.adp-consensus` cell (text = `mean.toFixed(1)`, `data-sort` =
   `padConsensus(mean)`) and `.adp-spread` cell (text = `String(sp)`,
   `data-sort` = `padSpread(sp)`). `round1(x)` = half-to-even at 1 dp,
   matches Python's `round()` (verified 0 mismatches over 200k random
   means). `padConsensus` pads `toFixed(1)` to 9 chars (matches server
   `%09.1f`); `padSpread` = `String(v+1000)` padded to 5 (matches server
   `%05d` of `spread+1000`). No checked ranks -> consensus `"–"` /
   `data-sort "999999999"`; <2 -> spread `"–"` / `data-sort "00000"`.
3. `resortByConsensus(t)` -- finds `thead th.adp-consensus`, sets
   `dataset.dir='desc'` then `.click()` so the shared sort flips it to
   ascending -> board back in consensus order for the current source set.
The `change` handler `stopPropagation()`s so it never reaches the form's
`hx-trigger` (no board re-fetch), and re-checks the last box if unchecking
would leave zero checked.

## Important Discoveries

- **`sleepermetrics.draft._fetch_adp_raw` is LIVE-FIRST, not snapshot-first.**
  It always tries `sleeper_adp(season)` and, on success, rewrites
  `season/adp/<season>.json`. So any networked run of the draft engine for
  the current season (e.g. a webapp route that assembles a Season, or a test
  script calling `board.combine('2026')` that reaches the Sleeper live path)
  silently rewrites `season/adp/2026.json` with fresh ADP. This happened
  twice this session; both times the change was reverted to keep commits
  scoped. `ffadp.sleeper.SleeperAdp` IS snapshot-first and shields against
  this for years that already have a committed snapshot. **When committing,
  always check `git status season/adp/2026.json` and revert an unintended
  refresh.**
- **RotoWire `adp.php` is a rich multi-site JSON table.** Columns include
  `average` (RotoWire consensus), `yahooppr`, `nffc12ppr`, `mfl12standard`,
  `ffpcoverall`, `underdoghalfppr`, `fantrax12ppr`, `espnppr`, `sleeperppr`,
  + per-analyst `rank_*`. `scoring=PPR` or `Standard` (other values return a
  91-byte empty). **No `year` param** -- current season only, verified
  (identical byte count for 2023/2024/current). Row keys: `firstname`,
  `lastname`, `team`, `position`, `playerID` (RotoWire's own id, no Sleeper
  cross-ref). Values are decimal strings; `""`, `"-"`, `>=999` are "no ADP"
  sentinels.
- **FantasyPros has NO no-auth path.** ADP pages (`fantasypros.com/nfl/adp/
  ppr-overall.php`) server-render only a ~5-row preview blob (integer ranks,
  no decimal ADP) inside a `<script>`; the full table is XHR-loaded from
  `api.fantasypros.com` which 403s without an HOF-subscriber `x-api-key`.
  Getting it needs the key (violates no-auth) or a headless browser
  (dependency the feature avoids). RotoWire's `average` is the public
  consensus substitute.
- **NFL.com Fantasy has NO no-auth ADP.** `api.fantasy.nfl.com/v1|v2/...`
  all 404; the draft-center page is a client-rendered Next.js app with no
  ADP in HTML; RotoWire's feed carries no NFL.com or CBS column. Probed
  thoroughly. The board is at the practical ceiling for no-auth sources
  (Sleeper/ESPN/Yahoo for apps, FFCalc/RotoWire for analysis).
- **FFC API** (`fantasyfootballcalculator.com/api/v1/adp/<slug>?teams=12&
  year=Y`): no auth, updated daily, free for commercial use with
  attribution. Slugs: `standard`, `half-ppr`, `ppr`, `2qb` (also `dynasty`,
  `rookie` -- not used). Returns `{status:"Success", meta:{...},
  players:[{name, position, team, adp, adp_formatted, times_drafted, high,
  low, stdev, bye}]}`. 2009 and earlier -> `status:"Error"`.
- **MFL API** (removed, but recorded): `api.myfantasyleague.com/<year>/
  export?TYPE=adp&JSON=1` -- no auth. Keyed by MFL numeric id only (needs
  `TYPE=players` for the id->name map). `IS_PPR=1/0` filter only bites from
  ~2019; older years need the unfiltered call. Names come back `"Last,
  First"`. MFL rate-limits aggressively (429s) on a fast snapshot-backfill
  loop -- needed 15-45s backoff.
- **Sleeper player dump carries `espn_id`, `yahoo_id`** (dropped by
  `sleepermetrics.players()`'s projection) but **NOT `mfl_id`**.
  `identity.py` reads the raw pickle directly.
- **ESPN ADP coverage by year:** 2015-2018 ~210, **2019 = 0**, 2020-2024
  ~350-470, **2025 = 0**, 2026 ~260. 2019/2025 are ESPN all-sentinel holes,
  not bugs. Endpoint `lm-api-reads.fantasy.espn.com/apis/v3/games/ffl/
  seasons/<y>/players?scoringPeriodId=0&view=kona_player_info` (~20MB,
  no auth, `limit` ignored). Undrafted sentinel ~170.
- **`SMTableSort` string-vs-numeric switch:** if ANY cell in a column has
  `data-sort` set, the whole column sorts by `localeCompare` on the
  `data-sort` string (not numeric). This is why the consensus/spread cells
  need zero-padded `data-sort` and why the pre-existing spread cell's bare
  `data-sort="{{ spread }}"` had a latent lexical-order bug (fixed this
  session by padding).
- **`TestClient` unavailable in this venv** (`httpx`/`httpx2` not
  installed). Route checks are via direct function calls on `webapp.app` +
  a fake `starlette.Request`, plus Jinja render with stub ctx.
- **`openpyxl`** is a real dependency (in `requirements.txt` + venv) for
  `.xlsx` export.

## Risks / Unknowns

- **`season/adp/2026.json` auto-refresh.** `sleepermetrics.draft.
  _fetch_adp_raw` is live-first and rewrites it on any networked
  current-season draft-engine run. A future session running the webapp or a
  broad test with network will dirty it. Check + revert before committing
  unrelated work (unless a genuine ADP refresh is intended).
- **RotoWire / ESPN / FFC endpoints are undocumented or informal.** They
  could change or start requiring auth. Mitigation: snapshot-first, committed
  history, graceful `[]` degrade. RotoWire is current-season-only so it has
  the least fallback depth (one committed year).
- **Client/server consensus parity** relies on `round1()` matching Python's
  `round()` and the padding formats matching. Verified this session (0
  mismatches over 200k means; `padConsensus` output byte-identical to
  `%09.1f`). If either side's formatting changes, re-verify.
- **`th.click()` re-sort depends on `SMTableSort` having wired the header.**
  Established that `home.html`'s `prepTables()` `afterSwap` listener is
  registered before `_adp_compare.html`'s, so it runs first. If that
  ordering ever breaks (e.g. the compare view's script moves), the
  post-filter re-sort silently no-ops (rows stay in prior order).
- **Testing tab is broken** (concurrent Draft-tab work, `sleeperboard`
  handler missing). Not ours. A full-tab render sweep would flag it.
- **Render ephemeral disk:** lazily-fetched historical snapshots (years not
  committed, or `?reload=1` output) don't persist across container
  restarts. Committed years are always available. Acceptable per the
  caching decision.
- **`verify.py` (R parity) not runnable here** (no Rscript). No parity code
  touched all session; a pass is still worth confirming when possible.
