## Architecture

### 1. Percentile radar: single overlay chart, not two charts

- `sleepermetrics/plots.py::plot_player_radar(season_profiles: dict,
  focus_season: str | None, player_name: str)` replaced the old two-
  function pair (`plot_player_radar` single-season + `plot_player_career_
  radar` career-trend). One radar now overlays EVERY available season
  (dashed/dimmed `_RADAR_GHOST`) behind the focused season (bold/filled
  `_RADAR_FILL`), sharing axis labels from the focus season's own columns.
- `webapp/player_profile.py::_all_season_profiles()` (renamed from the
  old `_career_percentiles`, which only tracked `fpts_ppr`) now returns
  the FULL per-season profile dict, keyed by season.
- `webapp/app.py`'s `/chart/player_radar` route reuses the EXISTING
  `season` query param as the radar's focus-season override (the
  `PLAYER_CHARTS` branch never reaches `pick()`, so `season` was
  otherwise unused there) -- see `_chartmacro.html`'s new
  `season_override` macro kwarg, which lets ONE call site (this chart)
  override the context `season` global without disturbing the other 41
  callers, which all still mean "league season."
- **Do not conflate `season` (league season, used by the back-link) with
  the radar's focus season again** -- this bit once already this session
  (see Rejected Approaches) and broke the back-link.

### 2. Percentile section: htmx in-place season toggle (no page reload)

- `webapp/templates/_player_percentile.html` (NEW file) holds the season
  pills + chart + stat table, imported by `player_profile.html` inside
  `<div id="percentile-section">`.
- New route `GET /player/{player_id}/percentile` (app.py,
  `player_percentile_part`) returns that same partial as an htmx fragment.
  Season pills are `<button hx-get=".../percentile?focus=YYYY..."
  hx-target="#percentile-section">`, not links -- clicking swaps the
  section in place (chart + table together), no full-page reload.
- `player_page`'s own route gained a `focus` query param, kept SEPARATE
  from `season` (which stays the real league season) for the same reason
  as above.
- `player_profile.html`'s inline `<script>` has `darkenCharts`/
  `fadeInCharts` helpers (dashboard's `prepCharts()` mirrored, since this
  standalone page loads no dashboard shell) wired to run both on initial
  load AND on `htmx:afterSwap`, plus an `htmx:configRequest` listener that
  rewrites `theme=light`->`dark` in the OUTGOING request path for
  dark-mode viewers (mirrors the existing `<img>`-src rewrite trick).
- A `#bar` htmx progress indicator (same one `index.html` uses) was added
  to this standalone page so a pill click shows visible loading feedback.

### 3. Team-defense (DEF) stats support

- **Root cause found via live API verification** (not assumption):
  Sleeper's real weekly feed DOES carry rich DST stats (`sack`, `int`,
  `tkl*`, `pts_allow*` tiers, `yds_allow*` tiers, `blk_kick`, `def_td`,
  `def_st_*`, etc.) for a DEF `player_id` (= team abbreviation) -- but
  `nflstats.py`'s `_USAGE_KEYS`/`_trim()` was offense-only and silently
  dropped every DEF row before this session.
- `sleepermetrics/nflstats.py`: added `_DEF_USAGE_KEYS` (verified against
  a real live fetch, 2024 wks 1-5, all 32 teams), branched `_trim()` by
  position, added `_LB_DEF_SUMS` + `_def_leaderboard()` for
  `player_leaderboard(pos="DEF")`. `player_usage()` explicitly SKIPS DEF
  (its columns -- snap_share/tgt_share/adot -- have no team-defense
  equivalent; forcing DEF through would silently produce all-zero rows).
- `webapp/sources/nflref/summary.py`: added `"DEF"` to `POSITIONS` (auto-
  populates the NFL Stats tab dropdown) and `_SLEEPER_DEF_COLS`.
  `leaderboard_columns("DEF", source="nflverse")` returns the SAME
  sleeper-shaped columns (nflverse structurally has zero DEF rows --
  confirmed, its `player_stats` release is individual-player-only, no
  team-defense grain exists upstream at all -- so there is no separate
  nflverse DEF column set to speak of).
- **Real bug found and fixed**: `percentile_profile()`'s percentile
  ranking assumed higher-raw-value-is-always-better, which is BACKWARDS
  for `pts_allow`/`yds_allow` (fewer allowed = better defense). Added
  `_LOWER_IS_BETTER = {"pts_allow", "yds_allow"}` and
  `rank(ascending=key not in _LOWER_IS_BETTER)`.
- **73 local, gitignored cache files** under
  `data/sources/sleeper_stats/*/week_*.json` had been written by the OLD
  offense-only `_trim()` and silently served incomplete DEF data even
  after the code fix (snapshot-first cache). Deleted (with user
  confirmation, since it's a destructive local-file operation) so they
  regenerate correctly from the live API on next access. This is NOT a
  git-tracked concern (directory is gitignored) but WILL recur on any
  other machine/environment with a pre-existing populated cache from
  before this session -- if DEF stats look incomplete elsewhere, this is
  the first thing to check.

  (`league_history.honors` -- user called it "generated/non-official

  -- only the template stopped rendering it. Every OTHER section (League
  history, Real-NFL history per-dataset, Draft ADP history) now shows:

  live data**: the Real-NFL history `{% for %}` loop used a bare

  any_current=false)` pattern; regression test added

  `{% set flag = true %}` inside a `{% for %}` without `namespace()`, it

  (`grep -rn "{% set .* = true %}"` near `{% for %}` blocks) if this
  class of bug is suspected elsewhere; not done this session, out of
  scope for a player-profile-focused pass.

## Important Discoveries

- **Native `<style>`/`opacity:0` chart-fade-in requires the dashboard
  shell's `prepCharts()`, which `player_profile.html` (a standalone page,
  no shell) never loads.** This was the FIRST bug fixed this session (the
  user's literal opening request: "inspect the player profile graphics...
  i just see a blank panel"). `weekly_report.html` had already solved this
  exact problem with its own small inline script; the fix here mirrors
  that one exactly rather than reinventing it.
- **`data/sources/sleeper_stats/` is a pure local runtime cache
  (gitignored), and stale entries from BEFORE a `_trim()`/`_USAGE_KEYS`
  change will silently keep serving old (incomplete) data indefinitely**
  since the read path is snapshot-first. Any future change to what keys
  `nflstats.py` extracts from a raw Sleeper line needs a matching local
  cache-clear, or verification against live data will show misleadingly
  broken results that look like a code bug but are actually a stale-cache
  artifact. (This bit directly this session -- the DEF fix initially
  looked broken in live verification purely because of this.)
- **Jinja's `{% set %}` inside `{% for %}` does not leak to the outer
  scope** -- confirmed via isolated Jinja2 test, then found as a real,
  pre-existing bug in this exact template. `namespace()` is the documented
  fix. Generalizes beyond this file (see Architecture #4's closing note).
- **`pandas.Series.rank(pct=True)` defaults to ascending=True (higher
  raw value = higher percentile)**, which is wrong for any "lower is
  better" stat (points/yards allowed). `ascending=False` inverts
  correctly and was verified with a small pandas snippet before trusting
  it, including the `na_option="bottom"` interaction (a NaN row's own
  rank distorts slightly but never affects a REAL row's own percentile
  reading, since that row is already excluded from the loop before the
  rank computation runs).
- **A Sleeper DEF's `pos_rank_*` fields are ALWAYS the `999` "unranked"
  sentinel** (live-verified, all 32 teams, week 1 2024) -- Sleeper does
  not compute real position ranks for team defenses the way it does for
  offensive players. Any DEF ranking/percentile has to be computed by
  this app from raw stat totals, same as the existing offense path
  already does via `nflstats.player_leaderboard`.
