### 2. Waiver wire / Free-agents sticky-header bleed-through

First pass (backing `<thead>`/`<tr>` opaque + an upward masking box-shadow)
did not fully fix it. User: "check against other scrollable tables for
inconsistency in structuring." Found two structural inconsistencies against
the app's OTHER sticky-header tables (`.roster-scroll`, `.draftboard`), both
of which pin cleanly:

1. **`border-collapse`.** `.roster-scroll` and `.draftboard` keep the base
   `border-collapse: collapse`. `.scrolltable` alone had been switched to
   `border-collapse: separate; border-spacing: 0` on the (long-stale) belief
   that collapse disables `position: sticky`. `separate` is the actual cause
   of the bleed: each `th` then paints an independent background box with a
   1px seam between cells that scrolled rows show through. Reverted
   `.scrolltable` to collapse (dropped the `.scrolltable table` rule
   entirely); collapse merges the borders so there is no seam.
2. **`.reportpanel` padding override.** `.card.scrolltable { padding: 0 }`
   (0,2,0) removes the top padding strip the sticky header would otherwise
   stick against. The Weekly tab wraps its body in `.reportpanel`, whose
   `.reportpanel .card.tablewrap { padding: 8px }` (0,3,0) outranked it and
   put an 8px sliver back above the header on the Weekly tab's Free-agents
   table -- while the Transactions tab's identical Waiver-wire table (not in
   `.reportpanel`) stayed flush. Added
   `.reportpanel .card.tablewrap.scrolltable { padding: 0 }` at matching
   specificity.

Sticky `th` block now (matches `.roster-scroll` structurally):

```css
.scrolltable table thead th { position: sticky !important; top: 0; z-index: 3;
  background: var(--surface); border-bottom: 0; box-shadow: 0 2px 0 var(--faint); }
```

`border-bottom: 0` + `box-shadow` = exactly one line in every engine (WebKit
drops a collapsed border on a detached sticky th). Removed the now-redundant
`thead`/`thead tr` background rules and a duplicated comment block.

### 2b. Visible header divider

Follow-up: user wanted a clearly visible header bottom border. First tried
bumping the `box-shadow` divider to `2px var(--faint)` -- still invisible.

Root cause: **`box-shadow` AND `border-bottom` on internal table cells are
dropped by Chrome/Firefox when the table is `border-collapse: collapse`**
(spec-undefined). Every prior header-rule attempt was silently a no-op; the
header only looked OK because of its opaque background.

Fix: draw the divider with an absolutely-positioned pseudo-element on the
sticky `th` (which is a positioned element, so the pseudo anchors to it and
paints regardless of border-collapse):

```css
.scrolltable table thead th::before { content: ""; position: absolute;
  left: 0; right: 0; bottom: 0; height: 2px; background: var(--faint); }
```

`::before` not `::after` -- the sortable sort-arrow already owns
`th.sort-asc::after`. `pytest` 93 passed; Weekly free-agents / Transactions
waivers / Draft finds all render 200.

Then user confirmed visible and asked to reduce it to normal thickness:
`2px var(--faint)` -> `1px var(--line)`, matching the body-row hairlines.
`pytest` 93 passed.

### 2c. Body-only scroll attempt -- REVERTED

User: "why does the vertical scrollbar interrupt the header row, shouldn't it
be limited to underneath it?" A plain `overflow-y: auto` on the `.scrolltable`
container runs the scrollbar the full container height, including next to the
sticky `thead`. No CSS property scopes a scrollbar to the tbody -- it needs a
body-only-scroll structure (`display: block` thead/tbody, tbody the only
scroller, per-table `<colgroup>` for widths since `display: block` kills the
auto header/body column sync).

Implemented that across `style.css` + all 4 templates. It broke the rendered
layout of every scroll table. **Reverted in full**: the 4 templates back to
HEAD (colgroups removed); `style.css` `.scrolltable` back to the

divider (the "visible now" state from 2b). The `border-collapse: separate`
hack that had been there before this session is also gone (plain `collapse`,
like `.roster-scroll` / `.draftboard`).

Lesson: HTTP-200 + no-traceback render checks do NOT verify CSS layout, and
this env has no browser. The first attempt's break was the `<colgroup>` not
being honoured once each `<tr>` became its own `display: table` box, so the

### 2d. Body-only scroll -- REDONE with flex, not `display: table` + colgroup

User: "review the vertical scroll bar planned adjustment for implementation"
then "yes" x2. Same goal (scrollbar beside the rows only), different mechanism
that sidesteps 2c's failure:

`style.css` `.scrolltable` block (rewritten):
- `.scrolltable table { display: block }`; `.scrolltable thead,
  .scrolltable tbody { display: block }`.
- `.scrolltable thead tr, .scrolltable tbody tr:not([hidden]) {
  display: flex; align-items: center }` -- **flex**, so column widths come
  from `flex` on the cells, NOT the table column model / `<colgroup>` (which
  was 2c's break). `:not([hidden])` guard is load-bearing: a bare
  `.scrolltable tbody tr` (0,2,1) beats the UA `[hidden]{display:none}`

  scroller now.
- `.scrolltable thead, .scrolltable tbody { scrollbar-gutter: stable }` --
  header reserves the body's scrollbar-width gutter so columns align (Chrome
  94+/FF 97+/Safari 18.2+; older = ~15px header misalign, not broken).
- `.scrolltable th, .scrolltable td { display: block; box-sizing:
  border-box; min-width: 0; overflow: hidden; text-overflow: ellipsis;
  white-space: nowrap; border-bottom: 0 }`.
- Row draws the divider: `.scrolltable tbody tr { border-bottom: 1px solid
  var(--line) }` (`:last-child` none).
- Sticky header moved from each `th` to the whole `thead`
  (`position: sticky; top: 0; z-index: 3; background`), with
  `thead tr { border-bottom: 1px solid var(--line) }`. No more `::before`
  pseudo -- `display: block` table means a plain `border-bottom` paints.
  `thead th { position: relative }` kept for the sort-arrow anchor.
- Per-table flex bases in `.st-wv` / `.st-fa` / `.st-wtx` / `.st-df` blocks,
  each `<class> tr > :nth-child(n) { flex: <g> <s> <basis> }` so header +
  body cells stay in lockstep. `0 0 <rem>` = hard width (numeric/rank cols);
  growing basis = Player/Manager absorb slack.
