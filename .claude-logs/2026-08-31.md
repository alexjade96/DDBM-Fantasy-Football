### 2. Forward season resolution: a pasted older-season league id reaches the
### league's current season (`league.py`, `season.py`, `webapp/app.py`)

  new opt-in flag; when true, resolves forward first. Default OFF so

  - `tab()` and every page-building route after `pick()` (`tab_part_view`,
    `report_weekly`, `report`, `report_redraft`, `playoffs_default`,
    `playoffs_scaffold`) set `league = d["resolved_league_id"]` so the pushed

### 8. Fix placement-tag label clipping in the playoff bracket chart

Follow-up to #7 (the new skeleton bracket made this visible for the first
time). `plot_playoff_bracket`'s "3rd-place game" / "5th-place game" / ...
italic tag, drawn just above each placement matchup's top card, was clipping
INTO that card.

Root cause: the label sat at `_top - CARD_HH - 0.13` with `va="center"`, so
half its glyph height bled downward into the 0.13-unit gap. Measured against
the skeleton bracket's real axes (a shallow 3-round tree, y-span well above
`_MIN_SPAN` so nothing was compressing it): 0.13 data-units rendered as only
~2.85pt of clearance, less than a 6.5pt label's own height.

Fix (`sleepermetrics/plots.py`): offset widened 0.13 -> 0.20 and switched
`va="center"` -> `va="bottom"` so the whole glyph sits above the anchor with
no downward bleed. The matching tint-band's top margin (0.14 -> 0.30) was
widened to match, so the tag still reads as inside its band rather than
poking out above it.

Verified: the 2026 skeleton bracket (screenshot) -- no clipping, tags clear
their cards. Regression-rendered 5 real finished brackets with placement games
(DDBM 2022/2023/2024, Coin Flip 2025) and 2 without (DDBM 2025's custom
bracket, 2024's 4-team bracket) -- all clean, no visual regression.
`consolation_bracket` chart (shares the same draw function) also still
renders. Not parity-gated (chart-only). Suite: 113 passed, unchanged.
