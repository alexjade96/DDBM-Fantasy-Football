{# The league-loading function, in the header -- same place and shape it sits on a loaded page (index.html's .utilbar). One box, auto-detected server-side (see app.py's /lookup): paste a league ID, a username, or a user ID, and it resolves as whichever one it actually is. JS fires an htmx.ajax GET to /lookup?nav=1 (nav=1 tells it this page has no dashboard shell loaded yet), dropping the response into #user-results. A LEAGUE match answers with an HX-Redirect, which htmx follows as a full navigation to /dashboard -- so opening a league from here still becomes the loaded index.html shell, not an in-place swap. A USER match (or no match) renders the "which of this account's leagues?" list in place, same as before; picking one there navigates to /dashboard?league=...&season=.... action="/dashboard" is the no-JS fallback -- name="league" so a plain form submit (JS unavailable) still resolves as a league id, the one case that route already supports without this new endpoint. The id is pre-filled with the Dank Soupers (DDBM) league so the default way in is one click. No season picker here -- nothing is loaded, so there are no seasons to choose. #}
